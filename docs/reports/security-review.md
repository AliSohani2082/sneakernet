### Evidence and limits

- S2's incomplete-manifest acceptance follows directly from `n > 0` being the only completeness condition. Installation uses a separately constructed required-file list and reopens source paths. Final destination renames are atomic but do not bind the verified input or secure intermediate directories.
- S3 is conditional: a normal host `/etc` and `/opt` controlled only by root prevent an ordinary user from creating those symlinks. A target mounted from USB/disk or pre-existing attacker-owned managed directory changes that assumption. `RemoveAll` does not recursively follow a final symlink; the concern during uninstall is unsafe parent traversal, not a claim that every final symlink causes recursive deletion.
- S4 logs pasted input through `readLine`, not just a hypothesis about Xray diagnostics. Normal configuration, servers, and state writes otherwise use appropriately restricted permissions.
- S8 was not dynamically reproduced: targeted existing race tests passed. Cancellation/startup-timeout branches require dedicated coverage before declaring the issue fixed.

## Positive controls and coverage notes

- Go subprocesses use `exec.Command`/`CommandContext` argument arrays; no share-link-to-shell command interpolation was found. Bootstrap/package scripts generally quote paths. Build-time Make variables remain trusted build inputs, not server-link inputs.
- Configs are generated through `encoding/json`, rather than interpolated JSON templates. The systemd unit and sysusers entry are embedded constants; link values cannot insert unit directives. XHTTP `extra` is explicitly supported raw JSON and is validated as JSON by the parser; semantic options should remain bounded to the supported Xray feature set.
- Installed `servers.txt` and `state.json` are 0600; service config is root:service-group 0640 (0600 without that group), and the config directory is set to 0750 with the service group. Config ownership is applied after atomic replacement. Broader problems are directory trust, pre-existing accounts, and credential copies on the USB/log.
- Temporary validation/probe configs use private `MkdirTemp` directories, 0600 files, and deferred cleanup. Bootstrap uses randomized `mktemp -d`. The main defects are source authenticity, inherited root execution, and untrusted parent paths rather than predictable filenames.
- The installed service uses `User`/`Group=sneakernet`, `NoNewPrivileges`, read-only system protection, private devices/tmp, and namespace/kernel/control-group restrictions. This is a useful baseline. `CAP_NET_BIND_SERVICE` is retained even for the default high ports; consider omitting it unless an explicitly chosen low port requires it. Test compatibility before adding address-family/syscall restrictions.
- TLS settings do not emit `allowInsecure`. Requests to disable certificate checks generate a warning; malformed certificate pins/post-quantum keys are dropped with warnings. Plaintext public VLESS/Trojan is flagged unusable. Loopback inbounds use no authentication, so all local users can use the proxy; that is an explicit deployment policy decision, not a remotely exposed listener by default.
- `versions.lock` pins four Xray v26.9.9 zip SHA256 digests. Fetch verifies downloaded archives before bundling/dev extraction. This guards downloads against bytes that differ from the trusted lock, but does not authenticate that lock's provenance or the resulting USB bundle. No signature verification exists in the reviewed code.
- Runtime does not extract tar/zip archives. Packaging uses `unzip` in a temporary directory after verifying the pinned archive, with no explicit member allowlist, link rejection, or expansion-size cap. Do not assume arbitrary malicious upstream archives are safe; harden extraction and close the verify/extract reopen race as defense in depth. No traversal exploit in the actual pinned archives was established.
- Current sysproxy handling prints fixed loopback URLs with numeric ports; no system-wide credential-bearing environment file or gsettings operation exists. Probe/validation inherit `os.Environ`, covered by S6. `convert` intentionally emits credentials as JSON to stdout and should be documented as sensitive output.

## Improvement suggestions

1. Make install/switch/remove transactional: stage and validate before replacing live binaries, server lists, config, or state; persist the manifest early enough to recover partial installs, and preserve/rollback previous state if service startup fails. Current `Apply` writes config before state, and list removal precedes regeneration.
2. Audit PATH-based helper resolution and command-link placement. `writableDir` checks root's write access, not root ownership or unprivileged writability. Accept only approved root-owned directories and do not replace an existing symlink unless its destination is this install's binary. Avoid treating supplied PATH as a trust signal for privileged commands.
3. Validate `--arch` against the supported enum, ports against 1–65535 and against one another, and region codes against letters/known data sets. Propagate scanner errors that callers currently discard, and report missing/invalid state rather than silently defaulting during edits.
4. Add meaningful adversarial regressions for required-manifest completeness, source mutation, parent/leaf symlinks, pre-existing writable directories, account collisions, secret-free logging, failed stops, and startup cancellation. Use disposable isolated roots; do not exercise destructive paths against the host.
5. Serialize state/list/account updates across separate CLI processes. Atomic rename avoids partial files but does not prevent lost read-modify-write updates. Sync containing directories where crash durability matters and preserve required metadata on account databases.
6. Bound subprocess duration and output in the service helper runner; `systemctl`, sysusers, and userdel currently have no context timeout. Preserve and display cleanup errors instead of making a successful-looking best-effort result.
7. For reproducible supply-chain checks, keep the trusted lock and Go sum provenance, pin container base images by digest, and make distro package update policy explicit. The container tests intentionally install system packages from live repositories; they are not an offline reproducible image build. The VM test script is currently an explicit unimplemented stub, so it does not validate Ventoy/live-session behavior.
